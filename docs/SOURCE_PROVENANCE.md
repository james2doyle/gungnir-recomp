# SOURCE_PROVENANCE — how third-party code enters this repository

Policy for importing any code, data, or asset not authored in this project.
The companion charter is `docs/LEGAL.md` (what may never be committed); this
file governs what *may* be committed and how.

## 1. License compatibility (we are GPL-3.0-or-later)

| Upstream license | Importable? | Conditions |
|---|---|---|
| MIT, BSD-2/3, Apache-2.0, ISC | Yes | Preserve copyright + license text; list in `THIRD_PARTY_LICENSES/` |
| LGPL-2.1+ (e.g. FFmpeg subsets, at3_standalone) | Yes, dynamic/relkink model | Preserve notices; keep the relink path documented; ship source or written offer per LGPL |
| GPL-2.0-or-later, GPL-3.0-or-later | Yes | Preserve notices; entire combined work remains GPL-3.0-compatible (GPL-2.0-**only** is NOT importable) |
| CC BY-NC-SA, CC BY-NC, "free for non-commercial" | **No** | Incompatible with GPL-3.0 and with any commercial future |
| Unattributed / unknown provenance | **No** | Provenance must be established first |
| Any license, for **game-derived** content | **No** | See `docs/LEGAL.md` §2.6 — translated game code is a derivative work regardless of the wrapper's license |

Derived *data* (e.g. NID→name tables) is treated like code: PPSSPP-derived
tables are GPL-tainted and importable **only with attribution**; preferred
source is BSD pspsdk headers, generated by our own tooling.

## 2. Import procedure (every import, no exceptions)

1. **Record provenance before merging:** upstream project, exact commit/tag,
   license (SPDX), what was taken (file list or "entire subtree"), and any
   local modifications. This goes in the per-subtree `PROVENANCE.md` (under
   `third_party/<name>/`) and is aggregated by `tools/package_notices.py`
   into `THIRD_PARTY_NOTICES.txt`.
2. **Pin it:** the exact revision goes in `dependencies.json`. Vendored
   subtrees carry the pin in their `PROVENANCE.md`; fetched deps are
   verified by digest in `cmake/Deps.cmake`.
3. **Preserve headers:** keep original copyright and license headers on every
   imported file. Add SPDX identifiers where missing. Do not relicense.
4. **Build from source where possible:** prefer pinned fetch/build over
   vendoring; never commit prebuilt binaries (no `.so`, `.dll`, `.jar`,
   `.zip` blobs in-tree — enforced by `tools/repository_check.py`).
5. **Quarantine copyleft quirks:** if a subtree has additional terms (e.g.
   GPL+Classpath exception, or a GPL component inside an otherwise-MIT
   tree), it lives in its own directory with its own LICENSE and is called
   out in `THIRD_PARTY_LICENSES/`.

## 3. Reimplementation over copying

When an upstream project has an incompatible license (or an unclear one) but
useful *behavior*, reimplement from the behavior description and record the
inspiration as prose in the relevant doc or commit message. Two specific
rules learned from the survey:

- **UI/UX lineage is not code lineage.** Touch-overlay layouts and player UX
  inspired by GPL projects (reVC/reIII family) must be independent
  implementations; do not port their code, assets, or layout data.
- **No "translation" of GPL code into another language** to dodge the
  license — a transliteration is still a derivative work.

## 4. Reference-only material

Some upstream projects are invaluable as *references* but must not be copied
from at all because of §1 or `docs/LEGAL.md`:

- Game-profile repositories that commit translated game code (e.g.
  PSPRecomp-family `profiles/*/generated/`) — read for architecture, never
  copy any generated unit, game-address constant table, or dump hash.
- Translation projects (e.g. gungnir-ptbr) — use documented *format facts*
  only (field layouts, archive structures); never take strings, scripts, or
  asset bytes.
- Emulators (PPSSPP) — behavioral oracle and NID-name source with
  attribution; **never linked or vendored** into the product.

## 5. What provenance is *not* required for

- Game facts: disc identity (redump), format layouts, NID values, guest
  addresses (see `docs/LEGAL.md` §3).
- Synthetic fixtures, shaders, input profiles, and documentation authored
  here.
- Tool output generated at build time (AOT units, notices, SPIR-V blobs) —
  generated artifacts are never committed in the first place.

## 6. Checklist for reviewers

- [ ] SPDX license identified and GPL-3.0-compatible (or properly quarantined)
- [ ] `dependencies.json` pin present and digest-verified
- [ ] `PROVENANCE.md` written; `THIRD_PARTY_LICENSES/` has the text
- [ ] Original headers preserved; no relicense
- [ ] No game-derived bytes anywhere in the import (`repository_check` green)
- [ ] No prebuilt binaries

## Reference review log

### `BasedYuki/the-3rd-birthday-recomp` — GPL-2.0-or-later

A Windows C toolkit whose runtime is explicitly PPSSPP-derived (`runtime/README.md`
and `runtime/CREDITS.md`), so **no runtime code is vendored**: the toolchain,
`sceAtrac` buffer model (`runtime/src/rt/atrac_hle.c`), savedata modes and SFO
handling (`runtime/src/rt/savedata.c`) are behavioral references only.

The project's PPSSPP automation is useful and independent of the product:
`tools/ppsspp_ws.py` speaks PPSSPP 1.20's WebSocket debugger, `tools/drive.py`
injects input/captures scenarios, `tools/oracle_save_dump.py` dumps loaded save
buffers, and `tools/save_import.py` imports PPSSPP saves. The T12b PPSSPP oracle
used `ppsspp_ws.py` out-of-tree (no file committed). Adopting any of these tools
later requires a pin, GPL-2.0-or-later notice and a `third_party/` provenance
entry; no code was copied into the runtime.

Also useful for T13: clean-boot versus savestate oracle discipline, the
screenshot/compare harness, and `tools/pace_test.py` for 59.94 Hz pacing.

### `Tzeentchnet/MetalGearAcid2-Recomp` — GPL-2.0-or-later

and input-script patterns (`tools/mga2/*.pad`), xBRZ/texture-replacement and
D3D12/Vulkan/software parity reporting, and the startup-skip UX. No code was
adopted.

### T13j reference review — texture-cache lifetime and eviction

The native-heap leak was fixed **after** an initial implementation, which was a
process mistake: `AGENTS.md` requires reference discovery before coding. The
missed review was done retroactively and changed only prose/validation, not
the code path.

- `hrydgard/ppsspp` (GPL-2.0-or-later), behavioral only, never linked or
  vendored. `GPU/Common/TextureCacheCommon.{h,cpp}` keeps `lastFrame` and
  `EstimateTexMemoryUsage` per entry, runs `Decimate` every 13 frames, and
  above `TEXCACHE_MIN_PRESSURE` (128 MiB) drops entries unused for
  `TEXTURE_KILL_AGE` (200 flips; 6 for CLUT variants, source comment cites
  `#10418`). GitHub issue `#21961` reports the secondary texture cache growing
  during video playback; `#19559` discusses content-addressed caching. No code
  copied.
- `AdamFull/psprecore` (MIT), behavioral only. `runtime/src/platform/gpu_vulkan.cpp`
  evicts GPU textures after `frame_number - last_frame > 240` and defers image
  destruction into the frame slot's garbage list. No code copied.

Our implementation differs in mechanism: draws hold `shared_ptr` owners for
the decoded image and source bytes, and the CPU/GPU caches are LRU byte
budgets (64 MiB / 512 entries, 128 MiB) with GPU destruction deferred to the
next idle frame. The sources above informed the size/age policy and the
deferred-destruction requirement; no upstream code, constants table, or file
was copied.

### T13i reference review — UtilsForUser GPI (bind, do not guess)

- `hrydgard/ppsspp` (GPL-2.0-or-later), behavioral only, never linked or
  vendored. `Core/HLE/sceKernel.cpp` implements `sceKernelGetGPI` as a read of
  the dev-kit switch bits and documents that they are always 0 on production
  hardware; `sceKernelSetGPO` only records the debug LED mask. GitHub issue
  `#19132` discusses the dev-kit-only GPO feature. No code copied.

Our handler returns 0 unconditionally, which is the retail value; no GPO state
is modelled because the title only reads GPI.

### T15 reference review — host save states

- `hrydgard/ppsspp` (GPL-2.0-or-later), behavioral only; never linked,
  vendored, or copied. `Core/SaveState.cpp` (`SaveStart::DoState`) defines the
  load/save order: quiesce utility IO, the SAS mixer and async IO, flush GPU
  pending drawing, then `Memory` -> `CoreTiming` -> `MemoryStick` -> MIPS CPU ->
  `HLEDoState` -> `__KernelDoState` -> filesystem (last, because kernel object
  destructors may close files) -> MMIO -> media engine. Section versions gate
  every block. `Core/HLE/sceKernel.cpp` (`__KernelDoState`) serializes the
  object pool first and then interrupts, kernel memory, threading, alarms,
  VTimers, event flags, mailboxes, modules, msgpipes, mutexes and semaphores in
  that order. `Core/HLE/sceAudio.cpp` (`AudioChannel::DoState`) keeps
  `reserved/sampleAddress/sampleCount/volumes/format/remainingSamples/
  waitingThread/waitingAddress` and carries a compatibility fix for a state
  that stored `waitingThread = -1`, which kept a channel busy forever.
  `Common/Serialize/Serializer.h` documents the Dolphin-derived chunk writer:
  versioned sections with 16-byte titles, no published format.
- Decision: our snapshot uses our own small versioned container (magic,
  version, corpus/config identity, TLV sections, payload hash). The reference
  format is GPL code without a public specification, so it is not copied or
  reimplemented; only the *ordering and completeness rules* inform the design.
- Decision: audio channels are saved as HLE state (including the parked
  waiter), while the mixer/AAudio stream and the GPU texture caches are
  rebuilt on load, matching the reference (GPU flushes on save, resets caches
  on load). This is also the likely field to inspect for the pre-battle stall.
