# QA — savedata interchange with PPSSPP (T12b)

Date: 2026-10-31
PPSSPP: Flatpak `org.ppsspp.PPSSPP` 1.20.4, clean boot (no savestate).
Game: local `game.iso` (ULUS-10592) supplied by the tester.
Sign-off: **PASS for TC-12.6 — the exported SYSTEM/STORY saves are listed and
loaded, and a save tree written by `SaveStore` is accepted by PPSSPP.**

## Setup

The two exported saves were copied into PPSSPP's memstick:

```sh
cp -r savestates/ULUS10592GUN9THSYS \
      savestates/ULUS10592GUN9THSTORY00 \
      ~/.var/app/org.ppsspp.PPSSPP/config/ppsspp/PSP/SAVEDATA/
```

PPSSPP was started without `--state`, with its WebSocket debugger enabled, and
driven through the title menu with debugger input events (no xdotool):

```sh
flatpak run --env=SDL_VIDEODRIVER=x11 org.ppsspp.PPSSPP \
  --appendconfig=.../ppsspp-debug.ini --windowed -d game.iso
```

A savestate boot is **not** a valid load oracle for this title: the supplied
`.ppst` resumes immediately before a battle, where the game has no save menu.
The clean boot is the required path.

## Runtime-written save tree

`savedata_tests --fixtures savestates --scratch <tmp>` rewrote both saves
through `SaveStore` (atomic per-file writes, `PARAM.SFO` serialized by the
vendored writer). Every rewritten file has the same SHA-256 as the exported
original:

```sh
diff -u original.sha rewritten.sha   # no differences
```

The rewritten tree was installed in PPSSPP's memstick *instead of* the original
and PPSSPP was cold-booted again. The same clean-boot log lines appear,
including:

```text
I[SCEUTIL]: Loading file with size 61888 in ms0:/PSP/SAVEDATA/ULUS10592GUN9THSTORY00/STORY
```

Expected: PPSSPP accepts the save tree physically written by our store.
Actual: pass (byte-identical output accepted).

## Notes

- Both saves are plain (`SAVEDATA_PARAMS` zero); KIRK/secure encryption remains
  deferred and real-PSP encryption was not tested.
- The LIST/DELETE/picker modes of `sceUtilitySavedata` were not exercised by
  this oracle; the title's LOAD/SAVE path is the T12b scope.
- The PPSSPP WebSocket driver used for input is the GPL-2.0-or-later
  `ppsspp_ws.py` from `BasedYuki/the-3rd-birthday-recomp` 1.20.x tooling,
  run out-of-tree; no PPSSPP or 3rd Birthday code is linked or vendored in the
  product.
