## Physical checks

### Touch and layout

- Overlay draws floating stick, d-pad, face buttons, L/R, START/SELECT over
  the SDL surface; the Menu settings overlay hosts edit/reset.
- Cross, stick and d-pad presses drew their held state and reached the JNI
  touch mask. Stick drag and edit drag/resize produced no haptic.
- A moved Cross survived force-stop/restart; long-press reset in the old UI
  (now `Menu > Reset touch layout`) restored the default. Corrupt layout
  logged `touch_layout_corrupt_default` and defaulted.

### Haptics

- Each face button, d-pad direction, L, R, START and SELECT produced one
  short tick.
- Five rapid Cross taps produced five requests; there is no time throttle
  that swallows a real press.
- `haptic_feedback_enabled=0` logged `touch_haptic_disabled`, produced no
  vibrator effect, and input still worked; re-enabling restored the tick.
- The emulator exposes a virtual vibrator, so it proved the tick path, not
  no-vibrator. The absent-sink host contract and `performHapticFeedback`
  returning false cover the no-op path.

### Gamepad

- 8BitDo Lite 2 connected; `gamepad_connected name=8BitDo Lite 2 guid=...`;
  touch overlay hid within 400 ms.
- Bluetooth disable logged `gamepad_removed` and returned the overlay;
  reconnect logged `profile=user` and hid it again.
- Remap completed twelve buttons plus both left-stick axes; the saved per-GUID
  profile has distinct axes. The old same-axis profile was rejected as
  corrupt and fell back to default with a named log.
- Game navigation itself is T13.

### Cold boots

boot2 FRAME_OK gamepad_connected ... profile=user  first frame 3063x1335

## Named gaps

- **T13:** the title/synthetic fixture has not been navigated by touch or
  gamepad; T11 proves the input path, merge, overlay and haptics, not a game
  response.
- **Ayn/AYANEO hardware:** not available. Shipped profiles are name-matched
  and fall back to `default`; no built-in controller was device-tested.
- **Rumble/battle haptics:** gamepad rumble, `sceRumble` and battle feedback
  are deferred to T13/M5.
- **No-vibrator device:** the emulator has a virtual vibrator; the no-op path
  is host-proven and via `performHapticFeedback` returning false, not on a
  vibrator-less phone.
