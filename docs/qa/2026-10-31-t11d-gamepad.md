## 1 — Connect and overlay hide

Build, install, launch with the controller paired:

```sh
scripts/android/build.sh \
  -Pgungnir.sdkDir=/opt/android-sdk \
  -Pgungnir.javaHome=/usr/lib/jvm/java-21-openjdk
ADB_SERIAL=30c1f958 scripts/android/install.sh
ADB_SERIAL=30c1f958 scripts/android/run.sh
```

The SDL adapter logged:

```text
I SDL/APP : gamepad_connected name=8BitDo Lite 2
            guid=0500821ac82d000012510000ffff3f00 profile=default
```

The touch overlay disappeared within the 400 ms poll (`t11d-connected.png`);
the Menu button remained. The Gamepad settings page showed the controller
name, GUID and `profile: default`.

Expected: a connected pad hides touch controls; the app keeps running.
Actual: pass.

## 2 — Disconnect returns the overlay

Bluetooth was disabled (`svc bluetooth disable`); the adapter logged:

```text
I SDL/APP : gamepad_removed name=8BitDo Lite 2
```

The touch overlay returned (`t11d-disconnected.png`). The app stayed on the
system driver with `first frame 3063x1335`.

Expected: removing the pad releases gamepad state and restores touch.
Actual: pass.

## 3 — Remap wizard

Menu > Gamepad > Remap opens a non-focusable dialog so the SDL surface keeps
receiving gamepad events. The wizard prompts through Cross, Circle, Square,
Triangle, L, R, Start, Select and the four d-pad directions, then the left
stick X and Y axes. The first build said "Press left stick"; the corrected
wording is "Push the left stick left/right" and "Push the left stick
up/down".

The first run saved a profile with `left_x_axis=0` and `left_y_axis=0`,
because the wording invited a second left/right push. The remap now rejects
reusing the X axis for Y, and the profile loader treats equal axes as
corrupt. A fresh run saved:

```json
{"id":"user","name":"8BitDo Lite 2",
 "guid":"0500821ac82d000012510000ffff3f00",
 "left_x_axis":0,"left_y_axis":1, ...}
```

The saved profile has the twelve captured buttons and distinct X/Y axes.
After force-stop/relaunch:

```text
I SDL/APP : gamepad_connected name=8BitDo Lite 2
            guid=0500821ac82d000012510000ffff3f00 profile=user
```

and the overlay stayed hidden. A corrupt/older/same-axis profile falls back
to the shipped default with `gamepad_profile_fallback: ...` and the app
still frames.

Expected: remap -> save -> reload is identical; invalid axes are rejected.
Actual: pass after the wording/validation fix.

## Gaps

- Game/synthetic-fixture navigation is T13; this report verifies the input
  path and overlay behavior, not a game response.
- Ayn/AYANEO hardware was not available. The shipped profiles are matched by
  device-name substrings; an unknown or different name uses the default
  profile. No built-in controller was device-tested.
- Gamepad rumble and battle haptics remain T13/M5.
- The remap wizard relies on SDL receiving gamepad events; the dialog is
  deliberately non-focusable. A focus change that hides the SDL surface
  would need a direct Android key/motion path.
