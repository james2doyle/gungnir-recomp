# QA — Android driver UI and fail-closed checks (T10d/T10e)

Date: 2026-10-31
App commits: `f8b33df` (T10d) plus `0d87f6b` (driver-list fix).
APK: debug, `com.gungnir.recomp`, versionName `0.1.0`.
Sign-off: **PASS for the driver UI, system-driver boot and fail-closed
matrix.** A real Turnip/custom driver was not available, so TC-10.2
(actual custom-driver load) is **NOT VERIFIED**.

## Devices

| Device | SoC / GPU | ABI | Android | Role |
|---|---|---|---|---|
| Xiaomi M2102K1AC (Mi 11 Ultra) | Snapdragon / Adreno | arm64-v8a | 14 (API 34) | primary phone |
| Android emulator `sdk_gphone64_x86_64` | SwiftShader | x86_64 | 17 (API 37) | system-only path |

The phone was unlocked. No driver archive was committed; the imported
packages were synthetic QA fixtures generated locally and removed after
the session. Screenshots stay in gitignored `build/qa/android/`.

## 3 — Synthetic arm64 package: import, select, fallback, delete

A synthetic zip with `meta.json` (`schemaVersion` 1, `name` "Synthetic
Turnip", `vendor` Mesa, `driverVersion` "Vulkan 1.3.999", `minApi` 28,
`libraryName` `libvulkan.so`) and a minimal ELF64 arm64 `libvulkan.so` was
placed in `getExternalFilesDir()/drivers/`. This is not a working driver; it
only exercises packing, metadata, selection and fallback.

Startup scan:

```text
I gungnir : driver_import_ok id=12770bcb4aeb7aa7 soname=libvulkan.so
```

A synthetic x86_64 package in the same folder was rejected:

```text
E gungnir : driver_import_failed: driver_elf_machine
```

Only `12770bcb4aeb7aa7` appeared in `files/drivers/`, with
`package.properties` containing the expected id, name, vendor, version,
`min_api=28` and soname.

Selecting the row wrote:

```text
custom=true
driver_dir=/data/user/0/com.gungnir.recomp/files/drivers/12770bcb4aeb7aa7
soname=libvulkan.so
hook_lib_dir=/data/app/.../lib/arm64
tmp_lib_dir=/data/user/0/com.gungnir.recomp/cache
```

Relaunch:

```text
I gungnir : driver_active=system name=Qualcomm Technologies Inc. Adreno Vulkan Driver ...
E gungnir : driver_fallback: driver_load_failed
I gungnir : first frame 3063x1335
```

Expected: the fake ELF cannot provide a usable Vulkan entry point; the named
fallback boots the system driver with no partial instance. Actual: pass.

The same package was imported through **Import zip** using the system
document picker from `/sdcard/Download/`; logcat again showed
`driver_import_ok`. Long-pressing the row and confirming **Delete** removed
the directory and `selection.txt`; the next boot returned to the system
driver. Actual: pass.

## 4 — Emulator system-only path

The x86_64 emulator dialog reports:

```text
Custom drivers require arm64-v8a. This device uses the system driver.
```

An injected custom selection on the emulator produced:

```text
E gungnir : driver_fallback: driver_abi_unsupported
I gungnir : driver_active=system name=gfxstream (SwiftShader driver) ...
I gungnir : first frame 640x320
```

A malformed selection file produced `driver_selection_invalid` and also
booted the system driver. Screenshots:
`build/qa/android/t10d-boot.png`, `build/qa/android/t10d-drivers-x86.png`.
